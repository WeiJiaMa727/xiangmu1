# 小马快跑秋招版邮箱 Pro

> 登录邮箱，自动整理你的秋招邮件；再配上企业投递资源库与投递进度看板 —— 从「看邮件」到「挑岗位」到「推进度」一站完成。

美乐蒂粉嫩主题 · React 18 + Vite + TypeScript + Tailwind CSS

## 新增：企业投递资源库（Pro 版核心）

登录后通过顶部导航切换三个板块：

| 路由 | 板块 | 说明 |
| --- | --- | --- |
| `/mails` | 邮件整理 | 原有核心功能：摘要提炼、截止日期排序、筛选搜索 |
| `/library` | **企业库** | 三级分类（行业 → 公司 → 岗位），31 家企业 / 60 个岗位，附官方投递链接、截止时间、投递要点 |
| `/progress` | **投递进度** | 看板（未投/已投/笔试/面试/offer）、近期待办、收藏夹、导出 Excel（CSV） |

企业库亮点：

- **三级分类导航**：左侧边栏按「行业（可折叠）→ 公司 → 岗位大类（跨公司筛选）」组织，移动端收起为抽屉
- **真实数据**：岗位与链接来自企业官方校招渠道，标注核对日期（2026-10-10）；无明确截止的岗位注明「招满即止」等原文
- **邮件联动**：自动把邮箱里的秋招邮件匹配到企业库公司（域名 → 别名 → 关键词三级匹配），岗位卡片显示「邮箱里有 N 封该公司邮件」，邮件行内显示「去投递 XX」一键跳转
- **搜索两级命中**：强命中（公司/岗位/地点）排前，弱命中（投递建议等）排后
- **收藏与进度**：点爱心收藏、下拉框标记状态，全部存在 localStorage，退出登录不丢失；导出的 CSV 带 BOM，Excel/WPS 直接打开不乱码

自检命令：

```bash
npm run verify:library   # 企业库数据完整性 + 联动匹配 + 筛选排序（46 项断言）
npm run shots            # 浏览器全流程截图与控制台错误检查（需先 npm run serve）
```

## 一、快速启动

### 推荐方式：单端口运行（最省内存、最不容易出错）

```bash
npm install --ignore-scripts
npm run build
npm run serve
```

然后打开 **http://127.0.0.1:8800** —— 一个端口同时提供页面和接口，不存在「页面在跑但接口没起」的问题。

| 命令 | 说明 | 内存占用 |
| --- | --- | --- |
| `npm run serve` | **单端口生产模式**（页面+接口，推荐日常使用） | 约 60-80 MB（限制堆上限 192MB） |
| `npm run dev` | 开发模式：前端热更新(5190) + 接口(8800) | 较高（Vite 开发服务约 200MB+） |
| `npm run doctor` | 真实连接自检（定位连不上的原因） | 瞬时 |

> 内存与磁盘：服务端限制了 Node 堆内存上限（192MB）；`node_modules` 与构建产物都在项目文件夹内，不写 C 盘系统目录（npm 缓存默认在用户目录，可用 `npm config set cache "D:\npm-cache"` 迁移）。

### 遇到「未检测到本地代理服务」？

按顺序排查（`npm run doctor` 会自动完成以下所有检查）：

1. **服务没启动** → 在项目目录执行 `npm run serve`，看到「本地服务已启动」后再刷新页面
2. **系统代理拦截** → 服务端已自动忽略 `http_proxy` 等环境变量并设置 `NO_PROXY=127.0.0.1,localhost`；如果你的系统代理软件（如 Clash）开启了「拦截回环地址」，请把 `127.0.0.1` 加入直连规则
3. **端口被占用** → 服务会提示换端口：`set PORT=8899 && npm run serve`
4. **依赖没装全** → `npm install --ignore-scripts`

## 二、两种登录方式

页面上可以随时切换，互不影响。

### 1）真实连接（默认）

真的连上你自己的邮箱，把邮件真的读进来。

1. 选择邮箱服务商（QQ / 网易 163 / Gmail / Outlook / 其他邮箱）
2. 填**邮箱地址**
3. 填 **IMAP 授权码**（**不是邮箱登录密码**）
4. 点「连接并整理邮件」

授权码获取方式（页面内点「怎么获取？」也能看到）：

| 服务商 | IMAP 服务器 | 获取授权码的关键步骤 |
| --- | --- | --- |
| QQ邮箱 | `imap.qq.com:993` | 设置 → 账号 → 开启「IMAP/SMTP服务」→ 生成 16 位授权码 |
| 网易邮箱 | `imap.163.com:993` | 设置 → POP3/SMTP/IMAP → 开启 IMAP → 新增授权密码 |
| Gmail | `imap.gmail.com:993` | **必须先开启两步验证**，再生成「应用专用密码」（普通密码无法登录） |
| Outlook | `outlook.office365.com:993` | 开启两步验证后生成「应用密码」 |
| 其他邮箱 | 手动填写 | 填该服务商的 IMAP 服务器地址，端口固定 993 + SSL |

### 2）演示体验

一键进入，使用内置的 18 封模拟邮件，含 1.5 秒模拟授权动效。
覆盖 6 类场景：明确未来截止日期、已过期、3 天内临近截止、无截止日期、中英文混合、非秋招邮件。

## 三、凭证安全说明（重要）

真实连接依赖一个**只监听 `127.0.0.1` 的本地代理**，原因是浏览器中的前端代码无法直连 IMAP（TCP 长连接限制 + 授权码绝不能下发到浏览器）。

代理的安全约束：

- 授权码**只在于本进程内存中**用于建立 IMAP 会话；**不写日志、不写磁盘、不回传前端**
- 服务端**不做任何持久化**，重启后凭证自动消失
- 前端调用的请求体里带授权码，但**不写入 localStorage、不进全局状态、不打印到控制台**
- 邮件**附件不会被下载**；正文裁剪到 4000 字符后再返回
- 退出登录会清除浏览器本地的会话与邮件缓存

## 六、边界情况处理

| 情况 | 行为 |
| --- | --- |
| 邮件正文为空 | 摘要显示「（无正文内容）」 |
| 日期格式无法识别 | 解析失败被 catch，`deadline` 返回 `null`，页面显示「—」 |
| 非法日期（如 2026-02-30） | 反查校验拦截，返回 `null`，不编造日期 |
| 残缺日期写法（如 `2026.10.3x`） | 正则负向断言拦截，不误判 |
| localStorage 数据损坏 | 自动清掉脏数据并降级，不白屏 |
| localStorage 不可用（隐私模式） | 自动降级为内存存储 |
| 代理未启动 | 登录页红色状态条 + 三步启动指引，连接按钮禁用防误操作 |
| 系统代理拦截 127.0.0.1 | 服务端清掉代理环境变量 + 设 NO_PROXY；前端请求失败自动回退直连地址 |
| 端口被占用 | 启动即提示，给出换端口与查杀进程的具体命令 |
| 授权码错误 | 返回中文提示，引导改用授权码 / 应用专用密码 |
| IMAP 连接超时 | 40 秒超时后给出网络与服务器检查建议 |
| 单封邮件解析失败 | 跳过该封，不影响整批 |
| 邮箱为空 | 提示可先用「演示体验」看完整效果 |

## 七、后续真实接入大模型

`src/services/summarize.ts` 顶部注释已标出完整替换方案：把 `runRuleBasedSummarize()` 换成服务端大模型调用，前端只请求自家后端接口。**务必保留 try/catch 兜底**，模型失败时降级回规则版。

密钥管理红线：密钥只能存在于服务端环境变量；Vite 中 `VITE_` 前缀的变量会进入浏览器包，**永远不要用 `VITE_*` 存任何密钥**。

## 八、不做的事

- 不接入 OAuth 跳转（真实连接走 IMAP 授权码，更贴近个人邮箱的实际可用方案）
- 不写任何数据库（无持久化，凭证重启即失效）
- 不引入 Ant Design / MUI / Element 等 UI 组件库（全部 Tailwind 手写）
- 不在代码中硬编码任何密钥
- 不下载、不上传邮件附件
